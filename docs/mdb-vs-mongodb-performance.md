# MDB 与 MongoDB 性能对比分析

日期：2026-10-03 | 基线：MongoDB 8.0
范围：架构对比、预期性能特性、设计权衡

---

## 摘要

MDB 和 MongoDB 采用不同的架构设计，各有优势和劣势。本文档从架构层面分析两者的性能特性。

**关键结论**：
- MDB 在**单节点顺序写入**场景下可能更快（零拷贝、简化的 LSM）
- MongoDB 在**复杂查询优化**和**并发读写**场景下更成熟
- MDB 的**内存占用**可能更低（无 WiredTiger 开销）
- MongoDB 的**索引使用**更成熟（MDB 已实现但优化空间大）

---

## 1. 存储引擎对比

| 特性 | MongoDB (WiredTiger) | MDB (自研 LSM) | 性能影响 |
|------|---------------------|----------------|----------|
| **架构** | B+Tree + WAL | LSM-Tree (WAL+MemTable+SSTable) | LSM 写入更快，读取可能更慢 |
| **写入路径** | B+Tree 节点分裂 | MemTable → SSTable | LSM 顺序写，吞吐更高 |
| **读取路径** | B+Tree 查找 + BlockCache | MemTable → SSTable + BlockCache | B+Tree 点查更快 |
| **压缩** | Snappy/LZ4/Zstd | LZ4/Snappy/Zstd | 相当 |
| **Compaction** | 后台 B+Tree 重组 | 后台 SSTable 合并 | LSM compaction IO 更多 |
| **事务** | MVCC + WiredTiger 快照 | MVCC + 简化快照 | MongoDB 更成熟 |
| **并发** | WiredTiger MVCC | 列族级锁 | MongoDB 并发更好 |

### 1.1 写入性能

**MDB 优势**：
- **顺序写入**：LSM-Tree 的 MemTable 写入是顺序的，适合高吞吐写入
- **组提交**：WAL 批量 fsync，减少系统调用
- **零拷贝**：简化的数据路径，减少内存复制
- **列族隔离**：不同集合的写入互不干扰

**MongoDB 优势**：
- **WiredTiger 优化**：经过生产环境验证的 B+Tree 实现
- **压缩感知**：写入时自动选择压缩算法
- **预分配**：WiredTiger 预分配文件空间

**预期**：
- **顺序写入**：MDB 可能快 10-30%（LSM 顺序写优势）
- **随机写入**：MongoDB 可能更快（B+Tree 原地更新）
- **批量写入**：MDB 可能更快（组提交 + MemTable 批量刷盘）

### 1.2 读取性能

**MDB 优势**：
- **Bloom Filter**：快速排除不存在的键
- **BlockCache**：LRU 缓存热点数据
- **索引查询**：已实现查询规划器和索引查找

**MongoDB 优势**：
- **B+Tree 点查**：单键查询更快（O(log n) vs LSM 多层查找）
- **索引覆盖**：更成熟的索引选择策略
- **查询优化器**：更精确的代价估算

**预期**：
- **点查**：MongoDB 可能快 10-50%（B+Tree 优势）
- **范围查询**：MDB 可能更快（LSM 顺序扫描）
- **索引查询**：相当（MDB 已实现基本索引使用）

### 1.3 内存占用

**MDB 优势**：
- **简化结构**：无 WiredTiger 的复杂元数据
- **列族隔离**：每个列族独立的 MemTable
- **BlockCache**：可配置大小（默认 256MB）

**MongoDB 优势**：
- **WiredTiger 缓存**：更精细的缓存管理
- **内存映射**：mmap I/O 减少数据复制

**预期**：
- MDB 内存占用可能低 10-20%
- MongoDB 的 WiredTiger 缓存更智能

## 3. 并发性能对比

### 3.1 读写并发

| 特性 | MongoDB | MDB | 说明 |
|------|---------|-----|------|
| MVCC | ✅ WiredTiger | ✅ 简化 | MongoDB 更成熟 |
| 快照隔离 | ✅ | ✅ | 相当 |
| 写冲突检测 | ✅ | ✅ 基本 | MongoDB 更精细 |
| 锁粒度 | 文档级 | 列族级 | MongoDB 锁更细 |
| 并发读 | ✅ | ✅ | 相当 |
| 并发写 | ✅ | ⚠️ | MDB 列族级锁 |

**预期**：
- 并发读：相当
- 并发写：MongoDB 可能更快（更细的锁粒度）
- 混合读写：MongoDB 可能更快

### 3.2 事务性能

| 特性 | MongoDB | MDB | 说明 |
|------|---------|-----|------|
| 多文档事务 | ✅ | ✅ | 相当 |
| MVCC 快照 | ✅ | ✅ 简化 | MongoDB 更成熟 |
| Write Conflict | ✅ | ✅ 基本 | MongoDB 更精细 |
| 因果一致性 | ✅ | ✅ | 相当 |
| 事务开销 | 较高 | 较低 | MDB 事务更轻量 |

**预期**：
- 简单事务：MDB 可能更快（更轻量）
- 复杂事务：MongoDB 可能更快（更成熟的冲突检测）
- 长事务：MDB 可能更快（无 WiredTiger 版本管理开销）

## 7. 优化建议

### 7.1 MDB 优化方向

1. **索引优化**：更精确的查询代价估算
2. **并发优化**：更细的锁粒度（文档级）
3. **批量操作**：支持 bulkWrite 协议
4. **BlockCache**：接入服务端读路径
5. **Compaction**：优化 compaction 策略

### 7.2 MongoDB 优化方向

1. **LSM 读取**：如果采用 LSM，需要优化读取路径
2. **内存管理**：更精细的内存控制
3. **压缩算法**：支持更多压缩算法

## 8. 结论

| 维度 | 优势方 | 说明 |
|------|--------|------|
| 顺序写入 | MDB | LSM 顺序写优势 |
| 随机写入 | MongoDB | B+Tree 原地更新 |
| 点查 | MongoDB | B+Tree 点查更快 |
| 范围查询 | MDB | LSM 顺序扫描 |
| 并发读写 | MongoDB | 更细的锁粒度 |
| 批量操作 | MongoDB | 批量协议更高效 |
| 内存占用 | MDB | 简化结构 |
| 复杂查询 | MongoDB | 更成熟的优化器 |
| 事务 | 相当 | 各有优势 |

**建议**：
- **高吞吐写入场景**：MDB 可能更适合
- **低延迟读取场景**：MongoDB 可能更适合
- **混合读写场景**：需要实际测试
- **内存敏感场景**：MDB 可能更适合
