# MDB 等保三级自评报告

## 1. 评估范围

本文档对照 **GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》三级** 要求，对 MDB 文档数据库进行差距分析。

## 2. 系统概况

| 项目 | 内容 |
|------|------|
| 系统名称 | MDB 文档数据库 |
| 系统版本 | v0.1.0 |
| 部署环境 | 信创环境 (麒麟/统信 + 国产 CPU) |
| 数据库类型 | 文档型 NoSQL 数据库 |
| 网络协议 | MongoDB Wire Protocol (TCP) |
| 安全特性 | SCRAM-SHA-256 认证、国密 SM3/SM4 |

## 5. 整改计划

### Phase 1: 核心安全功能 (1-2 月)
```
├── Week 1-2: TLCP/TLS 传输加密实现
│   ├── 密码套件: SM2-SM4-SM3 (TLCP)
│   ├── 证书管理: 自签/CA 签发
│   └── 握手协议: TLCP 1.1
├── Week 3-4: RBAC 权限管理
│   ├── 用户角色: readWrite, read, dbAdmin, root
│   ├── 集合级权限
│   └── 角色继承
├── Week 5-6: 审计日志完善
│   ├── 符合 GB/T 20273 格式
│   ├── 操作类型分类
│   └── 日志轮转/归档
├── Week 7-8: TDE 透明数据加密
│   ├── SM4-GCM 块加密
│   ├── 密钥层级: MEK → DEK
│   └── SDF/HSM 集成接口
```

## 6. 密评三级要求

### 6.1 标准: GM/T 0054-2018

| 要求项 | MDB 状态 | 差距 |
|--------|----------|------|
| 身份鉴别 (SM2) | 🟡 | 需 SM2 数字证书集成 |
| 通信加密 (SM4-GCM) | 🟡 | SM4-CTR 已实现，GCM 待完成 |
| 数据完整性 (SM3) | ✅ | SM3 已实现 |
| 数据保密性 (SM4) | ✅ | SM4-CTR 已实现 |
| 密钥管理 (SDF) | 🟡 | HSM trait 已定义，SDF 待实现 |
| 审计日志 | 🟡 | 需完善 |

### 6.2 整改重点

1. **SM4-GCM**: 替代 SM4-CTR，提供认证加密
2. **SM2 证书**: 实现 TLCP 握手
3. **SDF 接口**: 集成硬件密码模块
4. **密钥管理**: MEK/DEK 层级管理

## 7. 硬件密码模块需求

MDB 无法单独通过密评三级，**必须采购硬件密码模块**：

| 设备类型 | 用途 | 建议型号 |
|----------|------|----------|
| PCIe 密码卡 | SM2/SM3/SM4 硬件加速 | 三未信安、卫士通 |
| HSM 硬件模块 | 密钥管理 | Thales、Gemalto |
| SDF 接口适配 | 国密标准接口 | 需定制开发 |

## 8. 结论

MDB 在密码算法 (SM3/SM4)、身份鉴别 (SCRAM)、数据完整性 (CRC32C) 方面已有良好基础。主要差距集中在：

1. **传输加密** (TLCP/TLS) — 需实现
2. **权限管理** (RBAC) — 需实现
3. **审计日志** — 需完善格式
4. **透明加密** (TDE) — 需完成 SM4-GCM
5. **备份恢复** — 需实现工具

建议按 Phase 1-3 计划推进，预计 **3-4 个月**可完成整改并提交测评。
